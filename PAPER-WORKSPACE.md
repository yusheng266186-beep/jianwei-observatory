# Paper workspace — paper-v30

The public GitHub Pages address is unchanged. Paper preview is now a large,
bounded document workspace rather than a short continuous HTML table. The
content/settings panel starts collapsed. Desktop can edit alongside the paper;
narrow screens use a separate settings drawer. Compact controls, full-window
reading and a separate PDF window keep the actual document accessible.

## What is being previewed

The preview parses the real generated PDF using self-hosted PDF.js 4.10.38
(legacy build for broader browser compatibility). No report data is sent to a
third-party renderer. The same immutable PDF blob drives preview, download and
printing. The cache key uses canonical printed content and normalized layout,
ignoring transient chapter/source indices. The active preview blob is pinned for
export so cache eviction cannot replace it with newly generated bytes.

Pages have their actual dimensions, pagination, repeated headers and page numbers.
Fit width / whole page / 100% / zoom, previous/next, page entry, first/last and
chapter location are available. Text remains selectable. Page canvases render
near the viewport and release large rasters away from it; document placeholders
keep scrolling and total height stable. Closing destroys the PDF document and
its canvases. An obsolete async render never replaces the latest report.

Content changes indicate repagination immediately, including while the form's
repaint is debounced. New reader scroll actions take priority over an earlier
snapshot. Fresh reports start at the top. Resize/layout work skips invisible
print-media elements. Direct loading failures expose a retry control and never
block the rest of the application.

## Content and layout

Chapter inclusion, ordering, selected fields, per-chapter record filters, custom
titles, optional teacher judgment and source information remain reversible and
save with the combination. Independent report scope choices remain available.
New A4 settings cover portrait/landscape, compact/standard/spacious typography,
continuous chapters/new chapters on new pages, explanatory captions and empty
chapters. Wide fields split without losing identity columns or original scores.
The first chapter stays with the introductory material, avoiding a blank cover.
Oversized table rows can split rather than clip in PDF/Word.

PDF is the authoritative paper preview. Word uses the same chosen content,
direction, spacing and chapter settings, but Word/WPS can repaginate according
to installed fonts; that distinction is stated in the settings panel. Documents
remain monochrome. Printing uses the exact PDF pages at 144 dpi, with embedded
margins/page numbers and the proper A4 direction, rather than repaginating HTML.
Printed images and temporary print rules are released after print. For vector
printing or a different print resolution, the downloaded PDF can be printed
through the system's PDF viewer.

## Verification

Anonymous synthetic records only. `test:paper-workspace` covers four desktop and
mobile viewports, preview/download SHA-256 equality, real PDF text, original
question 19, zoom/page controls, independent scope/content settings, Word XML,
native browser print page count/orientation and saved combinations.
`test:report-reading` covers long reports, actual wheel/keyboard/touch scrolling,
last-page visibility, latest scroll intent during repagination, bounded canvas
memory and fresh-report reset. Composer, immediate-export, report boundaries
and storage audits cover associated paths. Unit tests validate normalized paper
settings, field preservation and semantic transfer.
