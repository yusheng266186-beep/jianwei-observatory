# 加载、动效与操作反馈打磨 · 2026-10-23

在21c7ae5之后，继续走查六个场景、报告、辅导及试题中心的正常动画和手机体验。这轮围绕点击之后的等待、内容就绪时的交接以及操作结果的位置做调整。

## 修复与调整

| 体验问题 | 调整后的行为 |
| --- | --- |
| 首次打开报告，等待可选CSS时没有窗口反馈 | 立即显示可关闭的加载窗口；取消后迟到样式不会重新打开报告 |
| 报告样式加载失败只能退出再找入口 | 窗口保留原观察，说明原因并提供原地重试 |
| 报告要等完整320ms入场动画后才开始整理内容 | 反馈绘制后即可整理，内容与窗口动画并行推进 |
| 慢网时加载外框与成稿宽度不同 | 基础样式预设相同外框；不依赖可选报告CSS才能正确布局 |
| 辅导表单出现、动画未结束时按Esc绕过草稿保护 | 加载关闭仅处理实际占位内容，表单关闭立即交由草稿保存流程 |
| 动画结束后定位标题，打断已经开始的输入 | 内容就绪时完成首次定位；已获得焦点的输入继续编辑 |
| 试题中心等待时只有按钮禁用，缺少解释 | 当前按钮显示打开、同步、提交、恢复或清理状态，并提供aria-busy |
| 下方练习操作失败后自动滚到顶部提示 | 原卡片附近显示原因，保留列表位置；键盘触发的操作完成后恢复焦点 |
| 确认删除后确认区立即消失，等待过程没有说明 | 保留确认区的删除状态；完成后收起，并将键盘焦点交回整理入口 |

报告与辅导共用轻量加载组件，样式放在已随研究界面加载的公共层。加载标记仅在等待时显示；减少动态或安静模式使用静态标记。原有玻璃材质、非线性窗口和场景运动继续使用原生命周期，没有新增逐帧JS循环。

异步按钮保留原尺寸与文案，处理状态经中心重绘后仍保留；结束时恢复原有禁用规则。提示文字沿用任务实际状态，不用虚构的百分比或完成倒计时。没有新增自动提交、自动重试生成或真实模型调用。

## 延迟对照

在相同匿名材料、390px视口、正常动画和人为延迟600ms的报告CSS请求下，对上一版与本轮构建做一次本机对照：

| 观察点 | 21c7ae5 | 本轮 |
| --- | ---: | ---: |
| 点击至可见加载窗口 | 629ms | 4ms |
| 点击至报告界面就绪 | 983ms | 628ms |

这是受控开发环境的对照记录，不能代表实际设备或网络保证。更稳定的回归断言是：样式请求尚未返回时已能关闭；样式已就绪时，报告内容能在入场结束前出现。

## 回归

`npm run test:interaction-polish` 使用匿名材料、受控本机请求和存储故障，覆盖11项场景：慢样式反馈与取消、动画内内容就绪、失败重试、表单出现瞬间的保存保护、恢复后重试及刷新、焦点连续性、按钮等待状态、重绘保留状态、下方卡片失败就地反馈、删除期间确认区反馈，以及320/390/1440宽度检查。Chromium与WebKit分别执行，并加入CI；截图与失败原因随CI归档。

原体验专项只把辅导加载提示的定位更新为共享加载组件，仍保留慢CSS阻塞、取消和迟到结果断言。单元测试、既有主流程、键盘/视口、前两轮可靠性专项、完整练习流程与报告文档回归继续执行。最终发布结果以同一提交的CI、Pages和线上逐文件回执为准。

旧试题中心专项改用带练习的完整匿名备份导入，替换工作区已就绪后直接写入底层数据库的测试注入，避免空闲预热先读到空库所产生的测试时序差异；仍核对原状态、检索、导出和布局。
