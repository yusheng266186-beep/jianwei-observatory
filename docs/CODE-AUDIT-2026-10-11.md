# 代码审核与修复 · 2026-10-11

按最新指令审核当前 `app/` 的数据流、统计查询、异步状态、DOM 更新和错误恢复。发现的问题先复现，再修复并增加回归。此次以匿名材料和故障注入检查程序行为，没有将真实姓名、身份证或原始成绩提交到仓库。

## 确认的问题与最终行为

| 范围 | 复现的问题 | 修复后的行为 |
| --- | --- | --- |
| 补充成绩 | 同考次只导入数学时，整行替换丢掉原有总分、其他学科和排名；未填语种还会变成英语 | 逐字段补充，空白保留旧值，实际0更新。成绩未变时保留排名；成绩改变且未提供新排名时，清除对应旧排名。未填语种不覆盖原语种 |
| 补充小题 | 作答中的空白覆盖已填分数 | 逐题补充，保留旧的已填分数，0分可以覆盖 |
| 题库顺序 | 题库换序或添加题目后，未补交作答的学生仍按旧数组位置读取，分数落到错误题目 | 按题号重排双方作答，再合并；新题无作答保持空白，旧题仍保留。换序涉及空题号或重复题号时明确拒绝，原工作区不改变 |
| 内部学生标识 | 不同姓名的备份采用相同内部ID时，新成绩挂到旧学生名下 | 冲突时生成新的内部ID，并重联成绩、小题及备份上下文 |
| 科类 | CSV中明确写了历史类，成绩记录属于历史类，但班级档案仍采用默认物理类，分组遗漏 | 班级档案沿用实际读入科类，同时识别 `history`、`physics` 和考试物/历后缀 |
| 早期考试增量 | 查看早期考试，默认对照取全局倒数第二场，可能拿本场与自己比较 | 默认使用当前考试的最近前一场；没有前一场时增量未知，显式对照必须存在且不是本场 |
| 跟进名单 | 同一学生同时有本科、特控两条跟进，更新状态后稳定DOM更新复用同一节点，名单少一条 | 相同键保留多个节点，各行只能被匹配一次，状态、文字和两条记录都保留 |
| 文件取消 | 在 `File.arrayBuffer()` 尚未完成时取消，迟到的读取继续建立Worker并重开列对应窗 | 文件读取、Worker消息及结束清理都检查本次读取序号；取消后旧任务不再影响新导入 |
| 导入提交 | 一个提交按钮禁用时，另一提交和关闭按钮仍能触发，造成重复写入和撤回快照错误 | 提交阶段同步锁定全部提交/关闭入口，只执行一次材料更新 |
| 保存结果 | 表单保存失败的提示被后续“已保存”覆盖；主动中止事务但 `tx.error` 为空时也被当作成功 | 失败只能报告失败；修改仍在当前页面，可下载完整备份。事务中止、超时及同步写入异常均拒绝保存 |
| 并发写入 | 等待数据库时输入对象被修改，写入内容不是调用时快照；后发写入可能被较迟完成的旧写入覆盖 | 调用时复制数据，同一模块的写入按发起顺序串行执行；失败不阻塞后续保存 |
| 工作区更新 | 材料、撤回快照、摘录分开写入，中途失败可能只完成一部分 | 三项在同一IndexedDB事务中提交或回滚。材料更新不能并发；数据库不可用时保留当前页面的修改与一次内存撤回，明确提示下载备份 |
| 研究夹恢复 | 连续打开同一场景的两条研究，先前操作迟到的抽屉覆盖最后选择 | 导航和渲染序号共同校验，只有最后一次恢复继续设置位置、条件及抽屉 |
| 导出重试 | 导出组件第一次加载失败后缓存拒绝的Promise，后续点击一直失败 | 失败释放缓存，重试只加载缺少的组件；超时和未初始化均给出可重试错误 |
| 判断草稿 | 资料仓输入新判断后立即刷新，400ms保存尚未执行，恢复成旧文字；新预览也可能尚未落库 | 输入时同步写本机草稿，数据库成功后才确认对应版本。刷新后恢复文字；尚未落库的新摘录连同完整证据一起恢复；旧保存完成不清除较新的文字 |

合并的含义是补充；需要主动清除旧分数或旧题目时使用“替换为这份材料”。导入窗口已写明空白、0和题号的处理规则。

## 验证范围

- 数据回归：`npm test`，16项通过。包括部分成绩、排名失效、题号对应、0/空白、ID冲突、科类和早期考试增量，以及此前的外语、17/18班、双上线、小题材料和备份上下文用例。
- 新增代码审核复现：`npm run test:code`，11项通过。真实Chromium中模拟空间不足、事务主动中止、延迟打开数据库、写入中途失败、文件读取延迟和导出网络失败。两种立即刷新用例均阻止摘录数据库写入，确认恢复来自草稿，而不是碰巧完成的异步保存。
- 原有浏览器流程：`npm run test:browser`，29项通过，覆盖六场景、Excel/JSON导入、备份合并/撤回、筛选、抽屉路径、报告、教师判断、文档下载和手机操作。
- 全场景复跑：`npm run test:surface`，18组通过；2770次操作、9类表单、1116次视图检查，未捕获错误与资源错误均为0。控件范围见[全场景检查记录](SURFACE-AUDIT-2026-10-11.md)。草稿修复后另外复跑了上述判断及原有浏览器流程。
- 动效回归：`npm run test:motion`，22组通过；本轮的导航序号修复继续保留最后一次选择，未重新引入截屏过渡或点击阻挡。
- 静态检查：ESLint 9检查当前36个应用模块，未发现所选规则的错误。规则覆盖未定义变量、不可达代码、恒定二元表达式、重复键、不安全finally、构造器、异步Promise执行器、多行歧义和typeof。静态检查不等同于业务数据正确性证明。

浏览器脚本先启动 `python3 -m http.server 4173`，再在另一个终端运行；可用 `AUDIT_URL` 指向部署地址。`CHROMIUM_PATH` 可指定本机Chromium。截图、匿名运行材料和详细结果保存在被忽略的 `.audit-output/` 中，不属于发布文件。

## 适用边界

本轮检查的是代码在可复现条件下的行为，未替代最新真实工作簿的逐项成绩核对。现有Excel联结仍以姓名为基础，跨班历史可保持连续；同名的不同学生需要可靠的唯一标识才能完全区分，本轮的内部ID冲突修复不把这个边界描述成已解决。多标签页同时编辑也不在本次同页面写入队列的保证范围内。

真实材料继续保存在用户浏览器。四表研究范围、英语与日语统一为折合后的外语、17/18班归入各自科类、导入前空白入口和六场景独立条件均保留。
