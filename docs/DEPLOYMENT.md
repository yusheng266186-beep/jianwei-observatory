## 发布前

1. 查看 `git status` 和当前分支，区分本次改动与未确认的其他修改。核对原表、任务和说明涉及的范围，不覆盖他人未提交内容。
2. 使用Node.js 22.9+及npm。可执行 `npm ci`、`npm run package:training -- --check`、`npm test`、`npm run build`、`npm run runtime:check` 和 `node tools/check-release.cjs`。共享契约有变化时先运行 `npm run package:training`；仅文档修改不需部署后端或调用模型。
3. 按变更范围进行验证：数据和导入修改用隔离工作区核对原表；界面修改检查桌面和手机；模型、图示或导出修改需补充针对性真实调用或文档核验。公开测试和截图使用匿名材料。
4. 核对运行清单、源码与相对文档链接，确认 `.nojekyll` 保留。源码变更重建后，提交相应入口HTML、清单与哈希资源，不能只提交源码。CI将检查全新安装、逻辑测试、构建、资源和生成一致性。
5. 把当前行为写入项目/后端手册；日期、失败经过和验证样本写入专题，再更新文档索引。历史记录保留原阶段语境。

成功发布依赖登记不是普通构建的替代步骤。有符合校验格式的上一轮正式回执时，可运行 `npm run runtime:record -- --receipt /私有路径/production-receipt.json` 后纳入本轮提交。回执要求 `verified`、`mergedTreeIdentical`、`productionMain`、`mergeCommit`、`sourceTree` 等字段，与本地提交树相符；字段名沿用兼容格式，不表示当前日常发布必须新建功能分支或PR。不能用未上线的构建冒充成功发布。详见[资源维护说明](IMPORT-AND-BUILD-MAINTENANCE-2026-10-18.md)。

## 正式发布

1. 将已核对的修改提交到 `main` 并推送，不另建日常预览分支，不强制改写主分支历史。
2. 等待 `Verify install and build` 的 `quality`、`browser-smoke` 作业，以及 `pages build and deployment` 完成。核对运行对应的实际提交，不能仅看到推送成功就判定上线。
3. 对比正式HTML、运行清单、哈希JS/CSS、Worker、两个独立页面及受影响文档，确认线上字节与对应提交一致；再实际打开受影响页面和关键流程。
4. 如果涉及训练服务，使用正式Origin验证必要接口与CORS。前端合并或Pages构建不自动部署云函数。
5. 在私有维护回执中记录提交、CI/Pages运行、资源核对和云端状态，避免将凭据或原始学生材料写入公开说明。

服务Origin沿用 `https://yusheng266186-beep.github.io`，正式与预览路径不需要分别加入CORS。服务地址分别由 `app/data/exercise-config.js` 和 `assets/model-workbench.js` 使用；变更时同步源码和构建，不能沿用另一服务的教师会话。

## 本机数据迁移与备份

升级正式代码继续读取正式站原有工作区，不会因本次合并自动采用预览材料。若在预览积累了新判断、练习和模板：

1. 在预览“材料与备份”下载完整 JSON 备份。
2. 在正式先下载现有工作区备份，避免误操作无法回看。
3. 到正式导入预览备份，按实际意图选择合并或替换。已有练习按记录ID归并、模板按归档规则合并；成绩空白不删除已有值，0可更新。
4. 核对学生数、考次、成绩、小题和教师记录，再继续使用。动态验证码仍使用现有认证器，登录会话不随备份迁移。

换设备、浏览器或域名同样需要备份迁移。本机试题中心是当前浏览器的目录，不承诺跨设备自动拉取全部云端历史。已接收任务关闭网页仍可继续；保留原工作区再回来查询。云端任务14天保留期内及时审阅导出。

## 后端维护

具体资源和凭据布局见 [backend/README.md](../backend/README.md)。正式站使用已部署的专属服务，名称保留 `-dev`；日常维护无需重建桶、函数、TOTP或模型配置。当前官方账号采用云端OAuth通道，旧计划通道已停用，详见[工作台整合](WORKBENCH-UNIFIED-2026-10-22.md)。

修改后端时先备份当前函数配置和代码包到仓库外私有目录，确认新代码、共用契约、环境变量、900秒事件函数时限、角色、COS通知和生命周期一致。部署工具会修改专属角色/策略/函数/桶配置，只在明确的后端维护任务中运行；不要把它当作前端发布步骤。复用 `training-private.json` 以保持认证器绑定和任务归属；不要为一次部署重新生成密钥。

普通代码修复优先只更新既有函数代码：部署前备份配置和代码，部署后回读比对代码包及环境、运行时层、角色、内存、网络和时限。保留当前官方运行时及代理层、`OPENAI_CODEX_*` 与 `OPENAI_PROXY_CONFIG` 等配置；早期完整初始化工具不能直接当作当前正式服务的一键升级命令。大任务状态响应可能声明`artifacts`，网页需经认证读取完整trace/图片分件；不要把只含占位的响应当作最终文档。

模型配置以私有 COS 的最新版本为准，重新部署的默认环境值不应覆盖工作台选择。调整额度或清零不会删除旧任务，也不能免除已产生的上游费用。

## 资源保留与过期页面

当前构建与最近3次成功发布、7天内已登记版本的依赖都会保留；以整个发布依赖图为单位，不按文件时间或单独截取几个 JS。源码、字体与手工资源不在自动清理范围。`npm run build` 成功写出资源后自动清理；单独 `npm run runtime:check` 只预览，`runtime:prune` 执行同一校验规则。

已打开页面若超出保留窗口，可能需要刷新。新版本在场景、辅导与试题中心组件失效时提供“刷新并继续”，不会自动重置材料或重发生成任务。尚未包含恢复代码的很旧页面需要手动刷新。删除部署目录中的历史包不会改写 Git 历史，也不承诺已有仓库完整克隆立刻变快。

## 回退

回退以本次发布前已验证的提交及私有云端备份为依据。前端采用新的revert提交并重新等待CI/Pages完成，不对 `main` 强制推送；回退前先导出当前本机工作区备份。旧版未必理解新增练习、图示、账号或教师记录，代码回退不等于数据库回退，也不自动清空浏览器资料。

历史的2026-10-17合并基线见[正式合并校检](PRODUCTION-RELEASE-2026-10-17.md)，不能把该固定旧提交当作以后每轮维护的默认回退点。

后端故障优先从模型工作台诊断、服务健康和私有任务日志定位，区分上游、传输、格式、图示和本机保存。需要回退云代码时使用私有已备份包并保留原凭据与控制数据；不要通过清空 COS 或新建 TOTP 处理普通错误。

## 常见问题

- 首页一直等待：先确认已发布入口与哈希资源可达，再看存储恢复、Worker或控制台。不要先清空资料。
- 正式没有预览练习：两条路径的本机空间隔离，按上面步骤导入完整备份。
- 验证码无效：检查认证器绑定、设备时间、重复使用和会话期限，不把服务地址或上游密钥当验证码。
- 生成变慢或失败：查看任务实际状态和诊断；估时不是终止倒计时。失败不自动跨服务重试，先确认原因再明确重新生成/继续。
- 导出不可用：确认必要图示完成、题文格式正确且当前版本已审题；修改后重新核对。文档缓存随内容版本失效。
- 新域名访问失败：重新核实来源允许列表和本机数据迁移；不得开放任意 Origin 或把私有任务桶改为公开网站。
