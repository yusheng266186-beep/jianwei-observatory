## 发布前

1. 确认分支、工作区和目标 main 没有未确认改动，核对 PR 的准确头提交；完整合并，不遗漏源码、运行资源、字体、提示词、后端、测试及说明。
2. 使用 Node.js 22.9+。在下一轮发布前，先用上一轮已核对的正式发布回执执行 `npm run runtime:record -- --receipt /私有路径/production-receipt.json`，将成功版本的完整依赖加入本轮提交。登记须提供 `verified`、`mergedTreeIdentical`、`productionMain`、`mergeCommit`、`sourceTree`，且与本地 Git 提交树相符；不能用未发布提交或仅构建成功代替。再运行 `npm ci`、`npm run package:training -- --check`、`npm test`、`npm run build` 及 `node tools/check-release.cjs`。后端共用契约变化时先 `npm run package:training`；核对生成差异是否预期。
3. 用实际文件在本机隔离工作区验证导入、数据、排名、报告、恢复和桌面/手机流程。截图与公开测试记录使用匿名显示，实际原文件和详细数据留在私有目录。
4. 检查运行清单中的所有资源存在、源码和文档的相对链接有效；扫描新增文件中的凭据、私有备份和真实材料。确认 `.nojekyll` 保留。运行 `npm run runtime:check` 应无待删资源；CI 用全新安装、测试、构建及生成文件一致性阻止遗漏锁文件或构建产物。
5. 更新 README、当前架构、后端说明、专题索引及发布记录，历史版本说明明确标为历史，不把旧“仅预览/未合并”当作当前状态。

## 正式发布

1. 将完整功能分支经 PR 合并到 `main`，保留可审阅的合并历史；核对 merge commit 的 tree 与已校检分支一致。
2. 等待主仓库的 `pages-build-deployment` 成功，核对构建对应 merge commit。失败先查看日志，不改用不相关分支或覆盖正式代码。
3. 逐文件核对正式入口、运行清单、哈希 JS/CSS、Worker、两个独立页面及说明文档，包含 `manifest.styles` 和成功发布清单的保留依赖；再实开六个入口和独立页面，检查控制台和关键动作。
4. 以正式 Origin 请求训练服务健康检查和 CORS；新前端沿用现有固定服务。静态文件合并不会自动部署云函数。
5. 在私有交接中记录源/合并提交、Pages运行、资源核对和后端状态，不记录到公开页面的凭据。

现有腾讯云配置允许 `https://yusheng266186-beep.github.io`，正式和预览只有路径不同，不需要改 CORS 或另发密钥。前端端点为 `app/data/exercise-config.js`，模型工作台独立脚本也使用同一端点；改地址须同步构建并重新验证，不能沿用另一地址的教师会话。

## 本机数据迁移与备份

升级正式代码继续读取正式站原有工作区，不会因本次合并自动采用预览材料。若在预览积累了新判断、练习和模板：

1. 在预览“材料与备份”下载完整 JSON 备份。
2. 在正式先下载现有工作区备份，避免误操作无法回看。
3. 到正式导入预览备份，按实际意图选择合并或替换。已有练习按记录ID归并、模板按归档规则合并；成绩空白不删除已有值，0可更新。
4. 核对学生数、考次、成绩、小题和教师记录，再继续使用。动态验证码仍使用现有认证器，登录会话不随备份迁移。

换设备、浏览器或域名同样需要备份迁移。本机试题中心是当前浏览器的目录，不承诺跨设备自动拉取全部云端历史。已接收任务关闭网页仍可继续；保留原工作区再回来查询。云端任务14天保留期内及时审阅导出。

## 后端维护

具体资源和凭据布局见 [backend/README.md](../backend/README.md)。本次正式合并复用已部署服务，名称保留 `-dev`；无需重建桶、函数、TOTP 或模型配置。

修改后端时先备份当前函数配置和代码包到仓库外私有目录，确认新代码、共用契约、环境变量、900秒事件函数时限、角色、COS通知和生命周期一致。部署工具会修改专属角色/策略/函数/桶配置，只在明确的后端维护任务中运行；不要把它当作前端发布步骤。复用 `training-private.json` 以保持认证器绑定和任务归属；不要为一次部署重新生成密钥。

普通代码修复优先只更新既有函数代码：部署前备份配置和代码，部署后读回比对代码包及环境、角色、内存和时限，避免完整重建工具覆盖已运行配置。大任务状态响应可能声明`artifacts`，网页需经认证读取完整trace/图片分件；不要把只含占位的响应当作最终文档。

模型配置以私有 COS 的最新版本为准，重新部署的默认环境值不应覆盖工作台选择。调整额度或清零不会删除旧任务，也不能免除已产生的上游费用。

## 资源保留与过期页面

当前构建与最近3次成功发布、7天内已登记版本的依赖都会保留；以整个发布依赖图为单位，不按文件时间或单独截取几个 JS。源码、字体与手工资源不在自动清理范围。`npm run build` 成功写出资源后自动清理；单独 `npm run runtime:check` 只预览，`runtime:prune` 执行同一校验规则。

已打开页面若超出保留窗口，可能需要刷新。新版本在场景、辅导与试题中心组件失效时提供“刷新并继续”，不会自动重置材料或重发生成任务。尚未包含恢复代码的很旧页面需要手动刷新。删除部署目录中的历史包不会改写 Git 历史，也不承诺已有仓库完整克隆立刻变快。

保留合并前主版本 `48cbc65c29f6aa334477559a82cc94ee6c38fe80`。如需回退本次合并，采用新的 revert 提交并重新等待 Pages 发布，不对 main 强制推送。回退前先导出当前工作区备份，旧版未必显示新增练习、图示或教师记录；代码回退不等于数据库回退，不自动清空浏览器资料。

## 常见问题

- 首页一直等待：先确认已发布入口与哈希资源可达，再看存储恢复、Worker或控制台。不要先清空资料。
- 正式没有预览练习：两条路径的本机空间隔离，按上面步骤导入完整备份。
- 验证码无效：检查认证器绑定、设备时间、重复使用和会话期限，不把服务地址或上游密钥当验证码。
- 生成变慢或失败：查看任务实际状态和诊断；估时不是终止倒计时。失败不自动跨服务重试，先确认原因再明确重新生成/继续。
- 导出不可用：确认必要图示完成、题文格式正确且当前版本已审题；修改后重新核对。文档缓存随内容版本失效。
- 新域名访问失败：重新核实来源允许列表和本机数据迁移；不得开放任意 Origin 或把私有任务桶改为公开网站。
