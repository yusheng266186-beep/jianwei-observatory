# runtime-v46：完整视觉下的启动、复用与作答材质

本轮按用户要求保留全部功能、成绩、小题、报告和视觉表现。整页横移、进入退出、快速改向、原有玻璃层、字体与动画时长没有删减。性能优化针对重复请求、主线程整理、重复计算与重复解析页面。

## 实现

- 学生作答与班级热力矩阵改为共用 `scoreStyle/scoreTone`，使用与题目卡片一致的柔和光泽、圆角与数字字重。保留深浅数据编码、实际零分、缺失、未知满分、异常值、题目打开、键盘焦点与强制颜色模式。密集表格原本没有逐格背景模糊，新材质也采用静态光照渐变。
- 首次空白首页只加载经典入口和独立的轻量存储模块，确认没有已有材料后呈现完整导入引导。读取已有材料时保留启动状态，避免误显示空白工作区。提前选择文件、多文件导入、拖入、模板、阅读设置及导航命令可交接到主应用。
- 导入期间准备后续研究模块及报告字体。JSON 备份无需下载 SheetJS；Excel/CSV 仍使用完整的本地工作簿库。
- 身份与排名归一化、材料合并以及恢复用的考试/班级/学生/试卷索引放到后台线程。主应用接收同一对象图内的材料与索引，原始记录引用和缺失含义保持一致。
- 已整理的数据与版本标记、随机保存标识在同一数据库事务中写入。再次打开复用整理结果，在后台恢复索引；规则升级会重新整理。用户备份中的标记不能绕过整理。迁移写入核对当前保存标识，防止迟到的任务覆盖新导入。
- 保存按调用顺序排队，异步整理不会改变快照或写入先后；数据库失败保留事务回滚和备份能力。
- 场景结果、章节结构与解析好的页面模板采用最多 8 项缓存。正常动效使用原有整页动画并复用页面模板；减少动态模式可保留可复用的实际页面节点。筛选、数据更改、教师记录与阅读偏好按状态更新，材料变更清理缓存。模块失败不保留被拒绝的加载任务。
- 重复点击已经处于相同条件的入口直接保留现有画布，按入口要求回到页首，不再解析和协调一遍相同页面；实际切换对象或筛选仍执行原有完整动效。
- 固定版本 esbuild 生成按内容命名的静态模块，共享代码拆分，样式合并；源码仍保留。字体与文档引擎完整保留，PDF 阅读与排版组件在进入报告操作时准备。

## 验证

- 135 项数据单元检查通过，包括后台索引交接的引用、统计、班级排名、零分、缺失和新材料缓存独立性。
- Chromium 与 WebKit 验证轻量首页、JSON 导入、再次打开、旧任务写入保护及六场景手机操作；两个引擎都验证延迟启动的已有材料恢复。
- 正常动效的桌面/手机六板块正反切换、快速改向、滚动退出位置、尺寸和动效偏好变化、学生对比浮栏、实际 Excel 再次导入通过。
- 11 项保存、取消、并发、事务回滚、失败重试与刷新草稿检查通过。
- CSV 学生识别码、同名档案、校排/班排、实际四表 Excel 导出和再次合并检查通过。
- 1440/390/320 像素下教师复核、完整材料、实际 PDF/Word、等待时关键内容及报告重新打开通过；PDF 文字渲染取消/缩放竞争检查通过。
- 统一材质和得分率颜色检查通过，涵盖零分、未知和异常，手机与纸面偏好。

## 实测范围

本机 Chromium、每次资源请求额外等待 90ms、CPU 四倍降速，使用仓库匿名化完整材料进行控制测试：空白首页从约 633ms、65 个 JavaScript 请求，变为约 327ms、2 个请求；已有材料首次恢复从约 1192ms、77 个 JavaScript 请求，变为约 989ms、16 个请求。后台索引接入主线程约 0.3ms。此测试人为延迟请求，不代表真实互联网或所有设备的速度；完整首屏布局和模块解析仍有成本。

保留正常整页动画，用 510 名匿名学生、900 条小题学科记录在桌面和手机各切换 12 次：内容可见的中位时间约 45ms，完整动画结束约 458ms，帧间隔 95% 分位为 16.8ms，没有长任务或超过 34ms 的帧间隔。动画结束时间包含原有过渡时长。

可运行 `npm run profile:runtime` 复测启动与完整材料切页，运行 `npm run profile:motion` 复测正常动效。网页发布前运行 `npm run build`，校检的是提交中的静态生成资源；访问入口继续使用固定站点地址。
