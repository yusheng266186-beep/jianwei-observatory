# 样式按需加载与跨端文档回归

本轮完成上一轮留下的三个方向：共享样式加载整理、各科文档回归、大数据及移动键盘检查。现有玻璃材质、字体、动画、功能和全部资料保留。此次不更换模型或修改云端出题规则。

## 样式加载与维护

`tools/style-groups.cjs` 是主站样式顺序的唯一清单。构建将它分成基础、报告阅读、共享研究材质、辅导和最终协调五包，入口保留五个有序链接占位。报告阅读及辅导包按对应入口加载；三个通用包并行准备，空材料首页仍只使用内联首页样式。

迟到的链接只设置原位置的 `href`，不会追加到共享协调层之后。相同链接并发请求共用一个Promise；网络失败或超时后允许重试，不缓存失败。页面及弹窗在使用专属样式前等待它完成，导航意图和已有预热减少实际点击时的等待。

`reports.css` 还包含教学计划和跟进公共控件，因此仍属于基础包。教学跟进入口、资料页导航也使用辅导包，不能只凭文件名将它们的样式延后。`paper-material.css` 同时用于班级/学生入口的小题与知识点观察窗，也保留在公共研究材质包中，不能只在访问试卷页后才加载。拆分时通过对照发现了跟进工具栏10px间距变化，已确认共享依赖并修正。16个390px/1440px页面及窗口的抽样材质、控件、尺寸对照一致，正常动画另由浏览器流程检查。

## 发现并修复的键盘问题

专项检查发现 `#exercise-dialog` 的ID规则仍用整个 `100dvh`，覆盖了通用弹窗的可见视口限制。键盘弹出后，窗口仍为832px高，超出380px可见区域。

该窗口现在使用与全站一致的 `--visual-view-height` 和 `--visual-view-top`，输入焦点随窗口可见区域调整，键盘收起后恢复。测试脚本也改为当前导入首页流程，并补上个性化辅导输入区检查。

Chromium、WebKit分别完成320px、390px、1440px下的21项检查：筛选、跟进备注、辅导训练重点、报告判断、长表末行、阅读设置及高度恢复，共42项。这里使用的是模拟VisualViewport事件，不能替代真实手机键盘、系统缩放和所有输入法的验收。

## 大数据与多尺寸

`tests/large-workspace.cjs` 创建独立匿名压力材料，不读取用户浏览器或调用模型：1236名学生、12个考次、14832条成绩、5000份练习。

- 两套浏览器均检查320、390、768、1440、1920px下六个场景，共60个页面组合，无页面横向溢出。
- 中心首次显示24份，加载更多后48份，搜索匹配准确；5000份原记录完整保留。
- 本机Chromium/ WebKit导入至确认完成分别约939/780ms，中心挂载约5/8ms。挂载口径不包含导航、网络或动画。
- Chromium记录到一次310ms的首次大数据处理长任务；没有将其描述为全程零卡顿。WebKit不支持同样的Long Tasks观测，空数组不能解释为无主线程占用。

这些数字是本机匿名样本记录，不是低端手机或真实公网的性能承诺。原始成绩范围、查询内容、动画和材料都没有缩减。

## 十科PDF与Word回归

`tests/fixtures/document-regression.json` 保存经过匿名处理的既有成稿选段，十科各三题，涵盖选择、填空、计算、解答、实验、写作、数学公式、化学式、数据表及矢量图示。日语来自此前单独高中语法/阅读/写作补测，未冒充原表知识点。

调用实际预览、PDF与Word导出函数，生成学生版和教师版，共40份文件。PDF检查每个题号、页面文字边界、纯空页；Word检查XML、题号、原生公式、表格和图形节点。固定样本的PDF页数及Word结构计数保存在 `document-layout-baseline.json`，修改基线需要重新渲染并核对。这些断言仅用于测试样本，不会成为教师生成内容的新限制。

本机用内置Poppler和内置LibreOffice渲染40份文件，共113页，逐页检查了字形、公式、表格、图示、页脚和分页。LibreOffice初始字体配置未包含中文，曾出现中文空白；为测试进程提供独立字体配置后重新渲染全部文件。没有将测试环境缺字体误判成线上Word导出丢字，也没有改动用户系统字体。Word应用、字体版本与PDF的具体分页允许不同，完整内容和可编辑公式保留。

这是成稿渲染回放，未调用付费出题或生图，不统计为新的模型成功率，也不能代替学科内容审定。

## 复核命令与持续检查

先启动静态服务器并安装浏览器：

```sh
python3 -m http.server 4173
npx playwright install chromium webkit
```

另一个终端运行：

```sh
AUDIT_URL=http://127.0.0.1:4173 npm run test:smoke
AUDIT_URL=http://127.0.0.1:4173 npm run test:keyboard
AUDIT_URL=http://127.0.0.1:4173 npm run test:large-workspace
AUDIT_URL=http://127.0.0.1:4173 npm run test:document-regression
AUDIT_URL=http://127.0.0.1:4173 AUDIT_BROWSER=webkit npm run test:keyboard
```

`AUDIT_OUTPUT` 可指定大数据或文档检查的输出目录。文档默认写入 `.audit-output/document-regression/`，用可用的文档渲染器及Poppler继续生成每页PNG做视觉复核。渲染器缺中文字形时，给该进程配置合法的宋体或思源宋体字体目录，重新渲染后再判断版式，不能只看XML判定视觉通过。

CI两套浏览器现在都执行12步流程、键盘及大数据检查，Chromium额外回放十科40份导出与版式基线；保存紧凑结果和截图。浏览器Job时限调至20分钟，包含浏览器安装时间。完整文档、逐页PNG及本机测量保存在本次本地验收目录，不提交真实资料或大体积渲染缓存。
