# 备份、恢复与导入一致性复查

本轮优先处理资料留存和失败恢复。DeepSeek V4.1 Flash 以 max 完成只读代码审查；下列复现与修复由主代理用匿名材料、实际浏览器和存储故障注入验证。没有读取真实学生文件、调用生产出题模型或修改云端配置。

## 已确认的问题与处理

| 问题 | 修复后的行为 |
| --- | --- |
| 导入已写入成绩，随后恢复练习失败，页面却仍持有旧材料 | 成绩、版本号、撤回快照、摘录、计划、练习、训练模板、导入列对应和出题草稿共用一次 IndexedDB 事务；任意集合写入失败，整次事务回滚。页面在成功后才安装新材料与版本。 |
| 删除过的练习从备份恢复后仍被删除记录隐藏，后续保存再次移除它 | 明确恢复成功后，只解除本次已恢复练习的删除记录，并取消对应练习和图片任务的待删除队列。辅导中心重新读取删除状态。其他已删任务保持删除。 |
| 备份把另一标签页已保存的出题草稿替换为本页的旧内存列表 | 正常保存完成时以同一次存储读取的集合为准；内存快照作为读取失败时的应急来源。保存失败时合并可恢复练习与草稿，文件标为“当前可恢复资料”。 |
| 旧页面导出旧成绩，却显示已备份当前资料 | 同时读取材料版本和备份修订。若其他页面已更新材料，仍保留本页应急下载，但不登记新的完整备份完成记录；提示保留文件并刷新后下载最新完整备份。匿名复现中，存储已为701分，而旧页仍为370分。 |
| 未保存的教学计划只在 localStorage，完整备份不包含它 | 增加 `workspaceDrafts`，保存未提交计划、编辑器状态与允许的文字日志。新浏览器导入后可继续编辑；已有本页草稿优先，普通成绩导入不回放旧草稿。 |
| 隐藏空章且筛选无结果后，预览无正文，导出按钮仍可点击 | PDF、Word、Excel与打印按钮按实际输出正文和教师判断判断可用状态，空预览显示调整方法。保留说明段落或教师判断时仍能正常导出。 |

工作区材料快照同时剔除首次导入时附带的练习、模板等旧副本。完整备份从当前集合读取这些内容，材料撤回不会因旧副本再次恢复已经删除的练习。

## 备份与存储边界

- 成绩与上述集合的提交受同一 IndexedDB 事务保护。收藏、研究夹和计划编辑草稿等浏览器偏好仍存放在 localStorage；它们不是跨存储系统的原子事务。备份会携带可迁移的草稿，草稿修改也会更新备份状态。
- `backupStatus` 记录本次文件是否完整以及缺失原因。旧版本备份没有此字段也能导入。
- “完整”表示本次已汇集当前可确认的工作资料，不表示浏览器已保证文件落盘，也不意味着多个设备已自动同步。
- 应急下载继续保留本页内容，不会为了读取最新材料而丢掉尚未保存的修改。另一个页面已更新成绩时，先保留应急文件，再刷新取得最新材料。
- 教学计划编辑器仍只有一个当前草稿。恢复备份时保留本机当前草稿；不会自动替换正在编辑的内容。
- 没有改变生成限制、学科提示词、玻璃材质或非线性动效。

## 验证

```sh
npm test
npm run build
AUDIT_URL=http://127.0.0.1:4175 npm run test:archive-reliability
AUDIT_URL=http://127.0.0.1:4175 AUDIT_BROWSER=webkit npm run test:archive-reliability
```

本轮单元测试1059项通过。`tests/archive-reliability.cjs` 使用Chromium与WebKit，在1440px和390px验证：

1. 在成绩 `put` 之后注入练习写入失败，确认材料、集合、撤回快照和版本号全部回滚。
2. 实际点击删除、确认删除、导入备份，确认练习重新可见，删除队列同步解除。
3. 本页已打开辅导中心后，另一页保存出题草稿和教学计划，备份保留这些新增内容。
4. 另一页修改成绩后，旧页应急文件保留旧值，文件名和状态均不冒充最新完整备份。
5. 未提交计划输入目标和说明，导出后在全新浏览器上下文导入，打开编辑器确认文字保留。
6. 实际打开没有正文的摘录，确认预览与四个导出按钮一致，手机和桌面无弹层横向溢出。

结果与匿名下载保存在被Git忽略的 `.audit-output/archive-reliability-*`。该专项已加入两套浏览器的CI。本机两套浏览器的12步完整冒烟也已通过；云端安装失败、超时或取消不计为通过。这里没有新增生产模型成功率结论。

## 后续优先方向

继续完善故障时的保留与恢复、跨页更新提示，以及大资料下的保存开销。先用明确复现和性能记录决定是否修改；不通过减少材质、动画或数据内容来加速。
