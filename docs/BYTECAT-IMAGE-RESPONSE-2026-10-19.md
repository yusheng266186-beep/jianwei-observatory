# ByteCat新分组生图接收修复（2026-10-19）

## 问题与处理

用户更换ByteCat生图密钥分组后，以既有 `gpt-image-2`、`/v1/chat/completions` 路径实测。该Web逆向线路这次返回原生风格的 `data[].url` 图片链接，而非旧聊天图片结构；不应因此改用未经验证的原生Images端点。

解析器兼容原有聊天、SSE、Base64及新图片链接结构。图片下载仅允许已确认的明确存储主机，新增精确主机 `pre-signed-firefly-prod.s3-accelerate.amazonaws.com`；不放行任意AWS域名，不跟随重定向，不向图片存储转发模型密钥。校验仍核对文件类型、PNG/JPEG签名和PNG尺寸。

云端复测确认上游已生成PNG，但下载超过旧3000000字节预算，被本服务拒收。下载、前后端单图及整份练习图片预算同步调整为3900000原始字节 / 5200000 Base64字符，保留原始像素，不降清晰度或裁图。单图结果留在5800000字节HTTP预算内；整份文档较大时仍由既有认证分件接口取图。私有COS对象读取预算为8MiB，容纳图片和最多2MiB教学正文，通用传输默认预算保持原值。

诊断只记录失败阶段、字节数、MIME及链接主机等结构信息，不记录签名查询、上游正文或图片载荷。若后续上游返回超过当前存储/传输容量的文件，仍会拒绝；本次扩容不代表图片大小无限。
