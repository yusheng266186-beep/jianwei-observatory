# 十科逐题出题设计 · 2026-10-29

出题页按“练习设置 → 逐题设计 → 核对生成”组织。第一步确定题量、用时、难度和教学依据；第二步选中题号，为该题选择知识点和题型；第三步补充整体目标、命题要求并核对逐题安排。桌面使用题目清单和知识目录并排布局，手机使用可横向切换的题目卡片与上下题导航。

## 知识体系

十科均有“按知识点”和“按教材”两种入口。知识体系采用“板块 → 子专题 → 考点分类 → 具体训练点”四级结构，支持搜索、语境或教材内容查找。按教材入口继续保留已核对的55册目录与原有训练点。两种索引可能涉及相同概念，数量不作为互不重叠知识总量相加。

## 每题独立选择知识点

每道题可以明确指定一个知识点，也可以保持自动。允许第1、2、5题使用相同知识点，第3题使用另一个知识点，其余题自动安排；没有“一知识点固定对应几题”的比例限制。选好某个考点后，可主动“用于全部题目”，再逐题修改。

知识点和题型分别编辑，修改题型不会删除该题知识点。增加题数保留原有行，新增行自动；缩减题数仅移除末尾题目的安排。切换学科、自动草稿、教学模板和多学生队列均保留逐题设置。知识点目录的高亮表示当前题的选择。

新请求使用 `targetMode: 'per-question'` 与 `questionPlan: [{id, target?, type?}]`。明确的 `target` 和 `type` 由逐题Schema、结果校验与内容复核共同落实。`targets` 在此模式下是自动题的候选范围，允许多于题数，不强制全部覆盖；不再为覆盖候选点而增加题数或重分配题号。内部仍有64项候选点和单项200字的请求容量边界，与“一个知识点几道题”的教学安排无关。

旧请求保留原契约和覆盖语义；旧草稿转入新建编辑时，把已有安排迁移到逐题计划，已完成和正在运行的历史记录不重写。分组冻结范围升为4，继续接受1/2/3版本。每组保留原卷计划的精确切片和完整候选范围，自动槽位不预先强制分配知识点；合并后按原题号核对。同一考点出现在前组不会导致后组省略题目。

生成后的覆盖摘要列出实际采用的知识点。质量提示不再把未采用的候选点标为漏出题；仍检查已明确指定的逐题知识点是否落实。

## 维护与验证

- `data/teaching/subject-knowledge.json`：九科主题分类、教材引用与独立训练点；数学继续使用独立知识源。
- `tools/build-subject-knowledge.cjs`：解析教材引用、检查ID/标签/请求长度，生成运行数据，避免复制修改两份教材内容。
- `app/data/subject-knowledge.js`、`app/ui/subject-knowledge-picker.js`：十科共用的目录访问和浏览组件。
- `app/engine/exercise-question-plan.js`：逐题迁移、题型与知识点独立修改、题量变更和候选池维护。

相关验证覆盖：十科分类与全量标签往返、同知识点复用、候选点多于题数、逐题知识点不能移位、草稿和模板恢复、6–12题分组精确切片、旧版本兼容，以及桌面1360和手机390/320、WebKit390的实际选择至匿名POST流程。额外提交一次6题真实云端任务，验证分组后重复考点仍保持原题号。发布与生成回执保存在当前任务输出目录。
