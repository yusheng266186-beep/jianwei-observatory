# 异步恢复与关闭保护 · 2026-10-23

在上一轮五项体验修复后，继续检查网络、存储和连续操作的边界，复现并修复以下三类问题。

## 已修复的问题

| 复现路径 | 修复前 | 修复后 |
| --- | --- | --- |
| 连接测试已发出，POST响应中断 | 清除本机任务ID并重新开放测试按钮，用户可能再次提交 | 保留原ID，仅GET查询确认；不自动重发POST，不创建新任务 |
| 编辑训练重点，草稿写入失败，按Esc | 未等待草稿保存就关闭窗口 | 等待草稿和练习保存；失败时显示原因并保留窗口、输入，恢复后可重试关闭 |
| 停止A轮比较后打开B，A的停止响应迟到 | B的结果被A覆盖 | 只有当前轮次的响应可以改写界面 |

第三类问题还覆盖了两条相同原因的路径：旧A查询的404会清空新B，旧A提交的响应会覆盖新B。这些请求现在都核对当前轮次及会话；同一轮并发查询只接受最新一次结果。历史切换等待期间不显示上一轮结果，也不允许误操作生成或停止，仍可切换另一条历史记录。

停止按钮按轮次分别跟踪：A正在停止时不锁住C的操作；切回A不会重复发送停止请求。A迟到的响应也不能解锁仍在停止的C。

## 不确定提交的恢复边界

- 提交前保存ID和最长60秒的未确认窗口，刷新后继续查询该ID。
- 网络、408或服务器响应异常不能证明云端未收到，因此查询原任务。短暂404在窗口内继续等待，窗口到期仍不存在则结束。
- 查询一旦找到任务，立即退出未确认状态，恢复正常轮询规则。
- 明确提交拒绝、无权限、参数错误或额度限制直接结束，不查询未创建任务。
- 主动“停止查询”仍只停止本机查询，云端已接收的测试可能继续运行。

这避免了响应丢失后直接开放重复提交。恢复不发送额外模型请求，也不尝试改变云端队列、额度或配置。

## 回归入口

`npm run test:continuation` 在Chromium和WebKit中使用匿名材料与显式模拟服务，检查：

1. POST响应丢失后仅查询原ID并读取完成结果。
2. 明确额度拒绝结束、不查询不存在的任务。
3. 未确认任务短暂404保留查询，刷新不重发POST。
4. Esc关闭遇到草稿写入失败保留窗口和最新文字。
5. 存储恢复后可重试关闭，刷新后恢复同一训练草稿。
6. 比较停止、旧查询404及旧提交响应不覆盖已打开的新轮次。
7. 读取另一轮时清除旧结果并保护生成、停止入口。
8. 多轮停止状态分别保留，迟到响应不解锁其他轮次。
9. HTML原稿下载及隔离放大预览保留。
