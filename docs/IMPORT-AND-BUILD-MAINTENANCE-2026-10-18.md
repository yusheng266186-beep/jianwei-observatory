## 构建与清理规则

- `npm run runtime:check` 只输出清理计划；`npm run runtime:prune` 执行清理；`npm run build` 在输出全部新资源后自动执行相同校验与清理。
- 清理前检查每个保留文件存在、路径符合白名单，检查保留 JS 的相对静态/动态导入都列入依赖集合。任一检查失败，本次不删除任何资源。
- 仅自动删除 app/runtime、assets、styles 内指定命名的哈希构建文件；原始模块、手工资源和字体不动。
- 成功发布清单初始纳入 e34848c8fb072e322330e29757e93bcff156e2ca、68f91266abfe4e10e33b1ea278855dd530fe6e22、b9413d7a4ebb2cfc9ebcdecabc7f9c0768379865 的完整 manifest 依赖。
- 下一轮发布前，用上一轮正式站逐文件核对通过的私有回执执行 `npm run runtime:record -- --receipt /私有路径/production-receipt.json`；核验成功标记、正式 main、merge commit 和 Git tree。构建不自行宣称发布成功；发布后不为了登记自身而修改已验收的提交树。
- 新增 CI 在 push/PR 执行 npm ci → npm test → build → runtime:check，并要求生成文件与提交完全一致。

本轮删除380个超期 JS、38个旧哈希 CSS，共41,983,717字节（约42MB），另移除464字节未使用图标；当前完整保留集合83个资源。当前部署体积缩小，但 Git 历史仍含旧 blob，不重写历史，也不把资源清理说成首页网络速度或完整克隆时间的保证。
