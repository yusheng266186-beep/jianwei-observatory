<a id="pipeline"></a>
## 任务处理与恢复

### 一次练习生成

1. 浏览器根据教师选择整理匿名训练要求，先保存请求和UUID。
2. HTTP函数验证来源、教师会话、请求结构与应用额度，创建不可覆盖的任务元数据，返回任务ID。
3. COS对象通知触发Worker。执行标记防止重复事件重复调用；较大练习按冻结的整卷安排分组处理。
4. 命题模型直接输出约定结构。可修复的格式错误携带原稿和具体诊断进入独立修复任务，默认沿用出题模型和思考强度，次数由工作台配置。
5. 学科复核检查条件、答案、题型、分值与评分依据，保留明确修订记录；不确定建议交给教师，确定且无法修正的问题不能伪装成合格成稿。
6. 必要图示按照题文给定的已知条件、标签、要求和版位独立规划、绘制，再核对题图关系。
7. 私有任务对象持续保存进度、部分成稿和最终结果；前端查询原任务并恢复显示。
8. 教师审阅、修改和确认当前文档版本，在浏览器导出PDF/Word并记录练后反馈。

请求字段仅允许学科、年级、教学范围、训练目标、题量、时长、难度、题型、图示策略、依据模式及最多24项匿名有效得分证据等约定内容。姓名、班级、学生标识、排名和完整成绩留在本机。真实0分有效；缺满分、缺分及异常分不能充当失分证据。

### 幂等、保存与继续

- 同一 `X-Request-ID` 对应同一请求；重连应先查询原ID，不能更换ID冒充重试。
- 元数据、执行标记和尝试槽使用不可覆盖对象，重复派发不会重复执行已接受的模型调用。
- 任务提交时冻结出题、图示、修复模型及档位、生图服务和官方账号；后续配置变化不改写已提交任务。
- 题组、内容复核、格式修复和图示分别持久化，继续任务只处理对应未完成部分。
- 成稿保存与交付恢复分开，已保存的候选可恢复落盘，不为一次读取或保存失败重新命题。
- 传输中断或完成状态不明时不盲目重发；仅能确定尚未发出模型请求等安全情况才进行有界恢复。

同题重绘先竞争尝试槽，再申请额度并创建任务。正常重放返回原ID及实际状态，手动重绘使用明确的新尝试。Worker事件批次默认最多并行处理2条记录；某条失败不抹掉其他结果。官方同账号的凭据刷新链另行串行保护，等待租约期间不发送模型请求。

<a id="api"></a>
## 接口分组

除健康检查、建立会话及OPTIONS预检外，当前业务接口需要有效教师Bearer会话。Origin允许列表和身份验证分别检查，CORS不能代替登录。

### 会话与练习

| 方法与路径 | 用途 |
| --- | --- |
| `GET /health` | 服务版本、当前模型公开信息、科目及验证类型 |
| `POST /session` | 使用六位动态码建立有期限的教师会话 |
| `GET /templates` | 取得学科提示词摘要，实际命题模板由云端使用 |
| `POST /jobs` | 提交匿名练习，`X-Request-ID`为UUID |
| `GET /jobs/:id` | 查询状态、进度、时间、结果及必要失败原因 |
| `POST /jobs/:id/resume` | 显式继续尚未完成的题组、复核、修复或图示 |
| `POST /figures`、`POST /illustrations` | 为已有题目提交图示重绘或复杂插图任务 |
| `POST /jobs/remove` | 写入云端任务移除标记 |

### 大响应与生成记录

| 方法与路径 | 用途 |
| --- | --- |
| `GET /jobs/:id/trace` | 取得完整生成记录或分段声明 |
| `GET /jobs/:id/trace/:part` | 取得指定生成记录分段 |
| `GET /jobs/:id/images/:questionId` | 取得对应题目的完整图像分件 |

组合状态响应超过5,800,000字节预算时可声明 `artifacts`，前端必须按声明取得完整内容。长trace按60万字符分段并携带同一内容哈希；快照变化时重新查询，不能拼接不同快照。分件同样要求教师会话，不通过公开COS地址绕过认证。

### 模型、额度与诊断

| 方法与路径 | 用途 |
| --- | --- |
| `GET /admin/models` | 模型目录、当前职责配置、历史版本和测试记录 |
| `POST /admin/models` | 按预期版本应用出题、图示、校检或生图选择 |
| `POST /admin/probes` | 创建独立连接测试任务 |
| `GET/POST /admin/usage` | 查询或调整每日上限、清零今日计数 |
| `GET /admin/diagnostics` | 指定时间范围内的脱敏任务诊断 |
| `POST /admin/diagnostics/import` | 将本机已知的任务ID补入诊断目录 |

模型与额度修改使用预期版本检查，冲突返回409，先同步再确认修改，不强行覆盖另一处设置。

### 云端官方账号

| 方法与路径 | 用途 |
| --- | --- |
| `GET /admin/codex/accounts` | 取得已保存账号、当前账号和可用额度快照 |
| `POST /admin/codex/accounts/active` | 按预期版本切换当前账号 |
| `POST /admin/codex/authorize` | 创建添加或重新授权任务，浏览器OAuth为默认方式 |
| `GET /admin/codex/authorize/:id` | 查询本次授权状态与必要的登录信息 |
| `POST /admin/codex/authorize/:id/callback` | 提交本次完整返回链接，由云端匹配并处理 |
| `POST /admin/codex/authorize/:id/cancel` | 取消本次授权 |
| `POST /admin/codex/accounts/:id/quota` | 排队读取官方额度 |
| `POST /admin/codex/accounts/:id/wake` | 排队发送一次轻量唤醒请求，会消耗实际额度 |
| `GET /admin/codex/operations/:id` | 查询额度或唤醒任务状态 |

### 鹈鹕模型比较

| 方法与路径 | 用途 |
| --- | --- |
| `GET /admin/pelican` | 最近20轮比较的摘要 |
| `POST /admin/pelican` | 创建1–8个模型的同题绘图比较，要求请求UUID |
| `GET /admin/pelican/:id` | 查询逐模型进度、HTML/SVG文档、原文及实际统计 |
| `POST /admin/pelican/:id/cancel` | 停止本轮，保留已完成结果 |

比较按模型串行派发，各项是独立Worker任务。原文、首段正文时间、总耗时和上游用量分别保存；缺失值不填造成0，单项失败不丢掉其他结果。新任务冻结 `promptVersion`、用户提示词与交付指令，默认与 Cockpit Tools 1.3.73 对应常量逐字一致，直接发送原文，不套练习JSON或SVG字符串Schema。Gemini请求使用 `text/plain`，Kimi不附加练习 `response_format`；普通练习仍使用各自原有格式。完整HTML及闭合代码围栏可提取为 `html` 与 `kind`，缺少完整文档时保留模型原文。历史SVG任务沿用原请求和结果，不自动重新计费调用。

浏览器通过独立预览页和双层 `sandbox="allow-scripts"` iframe 播放HTML，支持CSS、JavaScript及SVG动画，不授予同源权限。模型文档无法访问工作台账号、DOM或存储，预览CSP禁止联网和子框架。工作台自身仍保持禁止内联脚本的CSP；文档下载保留模型原稿。实现、来源及完整提示词见[HTML动画比较说明](../docs/PELICAN-HTML-2026-10-22.md)。

## 模型、提示词与图示

### 目录与配置来源

`model-control.cjs` 聚合已授权的提供方；`model-profiles.json` 和适配器处理型号、协议及思考档位。实际可见、已配置和当前选用是不同状态，目录存在不表示有余额或已经过真实调用。支持配置版本、历史选回及职责继承，已提交任务不自动跨提供方回退。

Kimi个人会员目录包含K3.1 Pro（`k3.1-pro`）、K3和K2.8 Preview，均按所选档位发送`low/high/max`；默认与当前选择保持原值。参见[K3.1 Pro接入说明](../docs/KIMI-K31-PRO-2026-10-24.md)。

CodeBuddy CLI API作为独立提供方，使用`CODEBUDDY_API_KEY`和固定`https://www.codebuddy.cn/v2`流式接口；目录包含14个CLI型号，按各自实际支持的档位执行。参见[接入说明](../docs/CODEBUDDY-API-2026-10-24.md)。

`model-performance.json` 只保存对应中转来源的公开TPS快照和日期。它不决定调用时限，不代替实时测试，也不构成成功率承诺。生图提供方独立选择和冻结，不随题文模型自动换密钥或分组。

### 命题要求与输出契约

- `templates.cjs`、`curriculum-boundaries.cjs` 和各学科规则约束四川高考课程范围与题型，允许原创情境和陌生材料，不把大学或竞赛知识设为必备条件。
- `teacher-brief.cjs` 和 `subject-scoring.cjs` 共同核对教师选择、训练点、题型、分值与评分口径。
- 共用契约限定3–12题、5–90分钟和五档难度，并检查教学选择的一致性。
- `document-format.cjs` 提供一次JSON编码、公式与表格规范的前置示例；程序不通过改写原稿伪造校验成功。
- 格式校检、学科复核、图题核对和教师审题各自承担不同职责，格式通过不能证明答案完全正确。

当前提示词版本为 `subject-templates-20261021.13`。可在仓库根目录导出实际编译文本：

```sh
node tools/export-training-prompts.cjs --out /绝对路径/新的导出目录
```

导出不调用模型、不读取账号密钥，使用匿名示例展示各环节。详见[提示词导出说明](../docs/PROMPT-EXPORT-2026-10-21.md)。

### 图示流水线

题文提供条件、对象、标签、精度与版位；图示规划据此选择无图、声明式SVG或必要复杂插图。SVG使用受控数据和共享绘制能力，复杂插图经已冻结的生图协议调用，再核对实际图片与题干关系。

图题核对失败应区分图示可修、题文本身有问题和仅影响排版的建议。保留原候选与具体反馈，不通过改图掩盖题目矛盾；教师改变题图关系后须重新核对。生图密钥、来源主机和容量限制以当前适配与私有配置为准，不能从某个历史分组的成功推断所有分组可用。

<a id="accounts"></a>
## 官方账号与代理

当前官方提供方为 **`openai-codex`**：

```text
统一生成入口 → codex-completion.cjs
             → codex-accounts.cjs（绑定账号、刷新租约、保存轮换）
             → codex-runtime.cjs（官方运行时）
```

使用现有ChatGPT/OpenAI账号进行浏览器OAuth，不需要另注册一个所谓“Codex账号”。跨设备无法直接到达回调时，在工作台提交本次完整返回链接；设备码仅作备用。回调检查本次状态和目标，交换后完成官方成功确认，才将账号标为可用。

- 官方账号、授权状态与额度跨设备由云端管理，网页不持有上游令牌，也不把返回链接持久化为浏览器凭据。
- 出题、图示与修复在提交时绑定当前账号；切换账号不改写已提交任务。
- 同一账号的刷新链使用租约串行保护，轮换凭据先持久化，再释放租约；不猜测过期时间盗用可能已消耗的刷新令牌。
- 并行生成在发出模型请求前等待账号租约，等待不等于重新生成；其他服务错误不因此反复重发。
- 额度使用官方实际返回值，主/次窗口缺失时不伪造。手动唤醒是一次真实轻量调用，会产生用量。

旧 `openai-chatgpt` 计划通道不再挂载面板或进入公开目录；启用当前通道的正式环境对旧授权接口返回HTTP 410。`openai-siwc.cjs`、`openai-credentials.cjs` 和旧本机助手等代码是历史实现，不是当前账号管理入口，不能混用两套授权令牌。

当前云端代理同步本地已更新的 **VLESS / Reality** 出站，`openai-proxy.cjs` 也保留原固定证书TLS配置的兼容。云端只监听 `127.0.0.1:18080`，保留Reality公钥验证及目标HTTPS证书验证；其他服务商和腾讯存储不改走该代理。更新代码时保留代理层、官方运行时层及相应环境配置。

具体实测和授权修复见[工作台整合](../docs/WORKBENCH-UNIFIED-2026-10-22.md)与[浏览器授权完成修复](../docs/BROWSER-OAUTH-COMPLETION-FIX-2026-10-22.md)。

<a id="security"></a>
## 认证、存储与限额

TOTP使用独立Base32种子、SHA1和30秒步长；当前允许窗口起点起100秒内验证，同一码只用一次。验证尝试与已用码通过不可覆盖对象跨实例共享，会话有效期为七天。

| 项目 | 维护原则 |
| --- | --- |
| 教师会话 | API持会话签名和TOTP配置，普通部署不重建种子或改变任务归属 |
| 上游API密钥 | 仅在执行端私有配置，不进入前端、备份或公开日志 |
| 官方OAuth令牌 | 放在加密的私有控制存储，按账号和授权版本隔离 |
| Origin | 精确匹配允许列表；同一GitHub域名下不同路径不需要分别放行 |
| 任务保留 | 普通任务前缀14天；本机已保存练习不因云端生命周期自动删除 |
| 控制保留 | 模型、账号及额度数据独立于普通任务生命周期 |
| 应用额度 | 工作台可调整，0表示应用层不限；清零不删除题目，也不撤回已发生费用 |
| 测试额度 | 模型连接测试独立计数，环境默认每日20次 |
| 执行时限 | 仍受事件函数900秒、具体适配与上游约束；估时不是保证完成的倒计时 |

试题中心主要是本机目录，不能据此承诺换设备后自动拉取所有云端历史。删除任务沿用界面的撤销／延迟提交流程，云端最终写入移除标记，不能撤销已发生的上游调用。

<a id="operations"></a>
## 配置和部署维护

### 先确认要改变哪一层

| 变更 | 所需动作 |
| --- | --- |
| 前端UI、交互或本README | 静态站发布；不会自动更新云函数 |
| 前后端共享训练契约 | 在仓库根目录运行 `npm run package:training`，核对生成差异，再测试前后端 |
| 后端普通逻辑修复 | 备份当前函数代码和配置，优先只更新代码包，回读比对 |
| 模型或每日次数 | 优先通过工作台按配置版本修改，无须重建云资源 |
| 代理或官方运行时 | 专门核对配置、运行时层和连接，不把它当作普通静态构建产物 |
| 新域名或服务地址 | 核对精确Origin、两个前端入口及本机资料迁移，重新构建验证 |

### 当前配置组

| 配置 | 用途与检查点 |
| --- | --- |
| `TRAINING_BUCKET`、`TRAINING_REGION`、`TRAINING_WORKER` | 专属任务存储与分发目标 |
| `TRAINING_SESSION_SECRET`、`TRAINING_TOTP_SECRET` | 原有教师身份与任务归属；保持稳定并留私有备份 |
| `TRAINING_ORIGINS` | 精确允许的网页Origin；不使用通配来源 |
| `TRAINING_MODEL_CONTROL`、提供方启用声明 | 启用工作台与当前服务目录；实际选择以控制区最新版本为准 |
| `OPENAI_CODEX_ENABLED`、`OPENAI_CODEX_BINARY` | 当前官方通道及运行时位置，执行端需保留对应层 |
| `OPENAI_PROXY_CONFIG`、`OPENAI_XRAY_PATH` | 私有代理配置与核心位置，API和Worker均保留原有配置 |
| 各上游密钥与生图配置 | 按提供方独立配置，不共享错误线路的密钥，也不从公开页面读取 |

普通代码更新后，确认环境、层、角色、超时、内存、网络和触发器均与备份相符，再验证当前官方账号、模型快照与具体任务。部署包、配置回读和凭据文件保存在仓库外私有目录，不写入公开提交。

`tools/deploy-training.cjs` 是早期完整资源初始化/配置工具，会修改角色、策略、桶生命周期、代码、环境和触发器，依赖旧私有文件布局。**它不是当前正式服务的通用一键升级命令。** 不应直接运行它覆盖已经包含云端OAuth、代理和运行时层的正式环境；确需初始化或重建时，先按当前代码核实工具、凭据与配置差异，再制定单独维护步骤。

<a id="diagnostics"></a>
## 验证与故障定位

### 日常检查

在仓库根目录执行：

```sh
npm run package:training -- --check
npm test
```

单元与逻辑回归覆盖请求匿名边界、身份和排名、原ID重放、事件去重、额度并发、协议、流式响应、图示、格式修复、官方账号租约和比较恢复。它们使用测试材料与可控响应，不证明真实上游一直可用；模型或图示变更须另做针对性调用与文档验证。

### 按失败层次处理

| 表现 | 先检查 | 恢复原则 |
| --- | --- | --- |
| 教师验证失败 | 绑定的认证器、设备时间、已用码及会话期限 | 使用新动态码，不重建TOTP |
| 账号需授权 | 官方账号状态、授权记录与刷新诊断 | 在工作台重新授权对应账号，不混用旧通道令牌 |
| 网页连接中断 | 浏览器到腾讯云的网络、CORS和本机代理 | 与云端到模型的连接分别定位 |
| 模型连接、余额或限流 | 对应提供方、分组、状态码与私有诊断 | 先查原任务，不把网络错误当成格式错误反复命题 |
| 完整回复格式不合格 | 原稿、契约诊断和修复任务 | 携带原稿与具体错误定点修复，保留已有内容 |
| 学科或图题问题 | 条件、答案、评分、图示候选与核对反馈 | 在有问题的环节修订，教师再次审阅 |
| 成稿保存或读取失败 | 保存候选、最终结果与分件声明 | 恢复交付，避免重复付费生成 |
| 前端目录缺少旧任务 | 当前浏览器、本机备份与云端保留期 | 恢复原工作区；不清空COS排查普通问题 |

公开响应只给必要的受控原因，原始诊断留在私有区。当前功能说明以本手册和实现为准，按日期归档的验证不能当作所有服务、模型和题量的永久成功保证。整理前的完整后端说明保留在[历史快照](../docs/HISTORY-BACKEND-BEFORE-2026-10-22.md)。
